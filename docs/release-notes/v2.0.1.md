## Added

- Graceful `Ctrl-C` handling: interrupting any command now prints a single
  `aborted (Ctrl-C)` line and exits `130` instead of unwinding as a raw Python
  traceback; the progress scroll region is released and mutating stages keep
  their recovery sentinel (1.2.0-F39)

## Changed

- `doctor` build-failure findings now also advise
  `sysforge state forget <pkg>` as the manual path for users who intentionally
  reverted to the repo package, instead of dead-ending at "clears on next
  successful build" (1.2.0-F34)

## Fixed

- `make release-resume` (`tools/release.sh --resume`) finishes an in-flight
  release when a post-tag failure required fix commits on top of the release
  commit — previously the exact-HEAD resume detection could never fire and a
  re-run computed a fresh bump from the already-bumped version (2.0.0-B1)
- Makepkg-bearing `run` verbs (`pipeline`, `packages`, `kernel`, `toolchain`)
  now fail fast with an actionable message when invoked as root, instead of
  surfacing makepkg's own refusal deep inside a build stage (1.2.0-B11)
- The reconfigure stage's "save editor as sysforge default" no longer silently
  fails on an installed system's root-owned `/etc/sysforge/sysforge.toml`; the
  write escalates via the same staged-temp-file + `sudo cp` path the
  makepkg.conf step uses (1.2.0-B13)
